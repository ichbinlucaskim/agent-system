# Lab 12 - The agent loop

## 목표

이 lab을 마치면 완료되거나 예산이 멈출 때까지 실행되는 자율 루프를 만들 수 있습니다. 명시적 중단 조건, step 예산, 비용 상한, tool 에러 시 재시도, 그리고 더 이상 진전이 없는 실행의 탐지를 갖춘 루프입니다.

## 사전 준비

Lab 00부터 07까지, 그리고 제한된 루프의 형태를 위해 lab 06. 개념: tool use 루프, 그리고 자율성은 그 한계에 의해 정의된다는 사실.

## 예상 소요 시간

60분에서 90분

## 배경

여기가 workflow가 agent가 되는 지점입니다. 이전의 모든 lab에서는 여러분의 코드가 다음에 무엇이 일어날지 결정했습니다. 여기서는 모델이 결정하고, 중단 조건이 발동할 때까지 계속 결정합니다. 차이는 그것뿐이며, 그래서 이 lab의 모든 내용이 한계에 관한 것입니다.

루프 자체는 짧습니다. message를 보내고, 모델이 요청한 tool을 실행하고, 결과를 덧붙이고, 반복합니다. 실제로 작성하는 코드의 대부분은 언제 멈출 것인가에 관한 것이며, 상한이 없는 루프는 agent가 아니라 끝이 없는 청구서입니다.

루프에 여러 개의 독립적인 예산을 주세요. 각각 다르게 실패하기 때문입니다. step 예산은 turn 수를 제한합니다. 비용 상한은 token 지출을 제한하는데, 한 step이 다른 step보다 훨씬 비쌀 수 있으므로 step 예산으로는 이를 제한할 수 없습니다. 실제 시간 마감은 사람이 기다리는 작업의 지연을 제한합니다. 가장 먼저 걸리는 것이 실행을 멈춰야 하고, 실행은 그것이 무엇이었는지 보고해야 합니다.

tool 실패는 정상적이며 대개 일시적입니다. 실패한 tool을 한두 번 재시도하고, 그다음에는 에러를 tool result로 모델에 돌려주어 모델이 다른 접근을 택할 수 있게 하세요. 둘을 분명히 구분해야 합니다. 재시도는 여러분이 다시 해 보기로 결정하는 것이고, 에러를 돌려주는 것은 모델이 다음에 무엇을 할지 결정하게 하는 것입니다.

가장 어려운 중단 조건은 진전 없음입니다. 막힌 agent는 크래시하지 않습니다. 같은 인자로 같은 tool을 호출하고, 같은 결과를 받고, 여전히 자신만만합니다. 최근의 행동과 관찰 쌍을 해시해서 최근 구간이 전부 반복이면 멈추는 방식으로 탐지하세요. step 예산만으로는 그 상태가 할당량 전부를 소진할 때까지 돌게 됩니다.

무엇이 실행을 끝냈든 결과는 그 이유를 말해야 합니다. 답변, 중단 사유, step 수, 지출을 담은 반환 객체가 운용할 수 있는 agent와 다시 시작하는 것밖에 할 수 없는 agent를 가릅니다.

## 단계

1. `AgentBudget`을 정의하세요. `max_steps`, `max_usd`, `max_seconds`를 가진 dataclass와, 수행한 step 수, 지출, 경과 시간을 추적하는 `RunState`입니다.
2. `is_exhausted`를 구현하세요. 예산 중 소진된 것이 있는지와 그것이 무엇인지 반환해서, 호출자가 사실만이 아니라 이유도 알게 합니다.
3. `run_tool_with_retry`를 구현하세요. 실패하는 tool을 정해진 횟수만큼 재시도한 뒤, 예외를 던지지 말고 에러를 tool result로 반환합니다.
4. `detect_no_progress`를 구현하세요. 최근의 행동과 관찰 쌍을 해시하고 마지막 몇 개가 전부 동일하면 True를 반환합니다.
5. `agent_loop`를 구현하세요. 모델이 tool 요청을 멈추거나, 예산이 소진되거나, 진전 없음이 탐지될 때까지 실행합니다. 답변, 중단 사유, step 수, 지출을 반환합니다.
6. `common.tracing`의 `Trace`를 붙여 각 step을 기록하고, 예산에 걸린 실행의 리포트를 출력하세요.

## 검증

```bash
pytest labs/track-3-autonomy/12-agent-loop/tests -v
```

모든 예산과 탐지기는 stub model로 오프라인 테스트됩니다. 통과했다면 루프가 step 예산에서 멈추고, 지출이 많을 때는 step 예산보다 먼저 비용 상한에서 멈추며, 실패하는 tool을 설정된 횟수만큼 재시도한 뒤 모델에 넘기고, 반복되는 행동 루프를 탐지하며, 항상 발동한 조건을 명시하는 중단 사유를 반환한다는 뜻입니다.

## 더 나아가기

- 모델이 완수할 수 없는 작업을 주고 어느 예산이 멈추는지 관찰하세요. 그것이 실제 안전 여유입니다.
- 매 turn마다 남은 예산을 모델에 알려 주고, 예산이 줄어들수록 우선순위를 다르게 정하는지 보세요.
- 진전 없음 탐지를 인자가 다른 재시도에 관대하게 만들고, 그 과정에서 진짜 루프를 못 보게 되지는 않았는지 확인하세요.
