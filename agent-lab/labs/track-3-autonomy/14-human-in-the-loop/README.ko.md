# Lab 14 - Human in the loop

## 목표

이 lab을 마치면 agent의 행동 경로에 사람을 둘 수 있습니다. 모든 행동을 자동, 확인 필요, 금지로 분류하고, 그 분류를 코드로 강제하고, 승인자가 실제로 무엇이 바뀌는지 볼 수 있도록 diff를 렌더링할 수 있습니다.

## 사전 준비

Lab 01, 07, 12. 개념: tool use 경계, 그리고 위험을 서열화하는 방법으로서의 되돌릴 수 있음.

## 예상 소요 시간

45분에서 60분

## 배경

`tool_use` block과 여러분의 코드가 그것을 실행하는 사이의 틈이 사람이 설 수 있는 유일한 자리입니다. 이 lab의 모든 내용이 그 틈에 있으며, 그래서 lab 01의 tool 경계가 중요했습니다.

tool의 어감이 아니라 되돌릴 수 있는지와 영향 범위로 분류하세요. 파일 읽기는 자동입니다. 파일 쓰기는 이전 내용을 파괴하므로 확인이 필요합니다. 이메일 발송은 취소할 수 없으므로 확인이 필요합니다. 프로덕션 데이터베이스 삭제는 금지이며, 그것은 agent에게 그 능력을 아예 주지 않는다는 뜻입니다.

금지는 코드로 강제해야 합니다. 절대 하지 말라고 말하는 system prompt는 요청이며, 요청이야말로 prompt injection이 덮어쓰도록 설계된 대상입니다. 어떤 행동이 절대 일어나서는 안 된다면, 그 tool이 agent의 tool 집합에 존재하지 않아야 하거나 실행기가 그 이름을 거부해야 합니다.

tool 이름만 보여 주는 확인 창은 사람들에게 승인을 누르도록 학습시킵니다. 승인을 실제 승인으로 만드는 것은 결과를 보여 주는 일입니다. 파일 쓰기라면 정확한 diff, 이메일이라면 수신자와 제목, 삭제라면 영향받는 행 수입니다. 승인 피로는 사용자의 실패가 아니라 설계의 실패입니다.

자동 승인은 대가가 있는 정책 결정입니다. 범위를 넓히면 agent가 빨라지고 위험이 그 뒤에서 실행되는 무언가로 옮겨 갑니다. 좁히면 더 안전해지지만 어느 지점을 넘으면 너무 느려져서 사람들이 우회합니다. 정책을 글로 적고, 한 곳에 모아 두고, 의도적으로 변경하세요.

자동으로 처리된 것을 포함해 모든 결정을 기록하세요. 문제가 생겼을 때의 질문은 항상 무엇이 승인되었고, 누가 승인했고, 실제로 무엇을 했는가이며, 그 질문은 당시에 남긴 기록으로만 답할 수 있습니다.

## 단계

1. `POLICY`를 작성하세요. tool 이름을 `auto`, `confirm`, `forbidden`에 대응시키는 하나의 매핑이며, 각 항목의 되돌릴 수 있음에 대한 판단 근거를 주석으로 설명합니다.
2. `classify_action`을 구현하세요. 행동의 정책 분류를 반환하되, 알 수 없는 tool은 `auto`가 아니라 `confirm`을 기본값으로 합니다.
3. `render_diff`를 구현하세요. `difflib`으로 쓰기가 정확히 무엇을 바꾸는지, 경로와 추가 및 삭제된 줄을 포함해 보여 줍니다.
4. `approve`를 구현하세요. 행동을 제시하고, 쓰기라면 diff를 제시한 뒤, 테스트에서 스크립트로 다룰 수 있도록 승인자 콜백에서 yes 또는 no를 받습니다.
5. `guarded_execute`를 구현하세요. 금지된 행동은 어떤 확인 절차보다도 먼저 거부하고, 자동 행동은 바로 실행하며, 나머지는 승인을 요구합니다. 모든 경로에 대해 감사 기록을 반환합니다.
6. 거부 사유를 추가하고 그것을 tool result로 모델에 되돌려 주어, 거부된 행동이 막다른 길이 아니라 정보가 되게 하세요.

## 검증

```bash
pytest labs/track-3-autonomy/14-human-in-the-loop/tests -v
```

정책 계층은 순수한 로직이며 오프라인으로 테스트됩니다. 통과했다면 금지된 행동이 실행기에 절대 도달하지 않고 누구에게도 확인을 요구하지 않으며, 자동 행동이 승인자 없이 실행되고, 확인 행동이 승인자를 호출하며 거부되면 실행되지 않고, diff가 추가된 줄과 삭제된 줄을 모두 보여 주며, 모든 경로가 감사 기록을 반환한다는 뜻입니다.

## 더 나아가기

- 평소에는 자동인 행동을 임계값을 넘으면 확인으로 격상시키는 규칙을 추가하세요. 예를 들어 파일 열 개 이상 삭제 같은 경우입니다.
- 대기 중인 여러 행동을 하나의 승인으로 묶고, 그것이 피로를 줄이는지 아니면 세부 사항을 감추는지 판단하세요.
- 거부된 행동이 사유와 함께 모델로 돌아가게 하고, 모델이 더 안전한 대안을 제안하는지 아니면 그냥 재시도하는지 보세요.
