# MemGPT: Towards LLMs as Operating Systems

<https://arxiv.org/abs/2310.08560>

Packer, Wooders, Lin, Fang, Patil, Stoica, Gonzalez. University of
California, Berkeley. 2023.

## 핵심 아이디어

비유가 곧 논문이고, 좋은 비유입니다. operating system은 RAM과 disk 사이를
paging해서 프로그램에게 물리적으로 존재하는 것보다 많은 memory가 있다는 착각을
줍니다. MemGPT는 prompt와 외부 저장소 사이를 paging해서 모델에게 창이 담는
것보다 많은 context가 있다는 착각을 줍니다. 창을 주어진 크기가 아니라 **제약된
memory 자원**으로 다룹니다.

계층은 두 층입니다. **main context**는 prompt입니다. 거기 있는 것은 이번 턴에
모델에게 보입니다. **external context**는 그 밖의 전부이고, 모델이 보려면
명시적으로 안으로 옮겨져야 합니다.

main context는 연속된 세 영역으로 나뉘고, 그 나눔이 설계입니다.

- **System instructions.** 읽기 전용. memory 계층이 무엇이고, 각 층이 무엇에
  쓰이며, 층 사이에서 데이터를 옮기는 함수를 어떻게 부르는지 기술합니다.
- **Working context.** 고정 크기 읽기/쓰기 블록이고, 함수 호출로만 쓸 수
  있습니다. 오래 갈 사실을 담습니다. 사용자가 누구인지, 무엇을 선호하는지,
  agent가 무엇을 약속했는지.
- **FIFO queue.** 굴러가는 메시지 이력. 첫 칸에는 이미 밀려난 것들의 **재귀적
  요약**이 들어갑니다.

외부 저장소도 갈립니다. **recall storage**는 전체 메시지 이력을 담고,
**archival storage**는 agent가 남기기로 한 임의의 텍스트를 위한 읽기/쓰기
데이터베이스입니다.

**모델이 자기 memory를 관리합니다.** 이것이 이 논문을 context 다듬기 라이브러리
이상으로 만드는 주장입니다. memory 편집과 검색이 자기 주도적입니다. 모델이 함수를
불러 working context에 사실을 쓰고, recall storage를 검색하고, archival storage에
무언가를 보관하며, 그 시점을 스스로 정합니다. system instructions가 계층 설명과
그것을 가능하게 하는 함수 schema를 지고 있고, 이는 memory 정책이 prompt로 쓰여
있다는 뜻입니다.

돌아가게 만드는 장치가 둘입니다.

- **사건으로서의 memory pressure.** prompt가 한계에 가까워지면 시스템이 경고
  메시지를 끼워 넣어, 무엇이 사라지기 전에 중요한 것을 저장할 기회를 모델에게
  줍니다. flush 임계를 넘으면 queue manager가 메시지 묶음을 밀어내고 그것들을
  새 재귀적 요약에 접어 넣습니다. 밀려난 메시지는 recall storage에 남아 검색
  가능하고, 잃는 것은 창 안에 있다는 사실뿐입니다.
- **사건 기반 control flow와 chaining.** 추론이 사건으로 발동되고, 사건에는
  사용자 메시지와 시스템 경고와 예약된 타이머가 포함되므로 agent가 재촉 없이
  움직일 수 있습니다. 함수 호출에 제어를 즉시 돌려 달라는 flag를 붙일 수 있어서,
  모델이 호출을 연쇄할 수 있습니다. 결과 페이지를 넘기거나 여러 질의의 결과를
  모으는 일을 하고 나서 양보합니다. flag가 없으면 양보하고 다음 사건을
  기다립니다.

함수 결과는 가득 찬 working context에 쓰려 한 경우 같은 **런타임 오류까지 포함해**
다음 입력의 일부로 모델에게 되돌아갑니다.

## 무엇을 해결하는가

context 창은 유한하고, 늘리는 값은 제곱으로 들고, 그리고 논거의 더 날카로운
절반은 이것입니다. 창이 커도 모델이 그 여분을 잘 쓰지 못합니다. 그렇다면
생산적인 수는 더 긴 창이 아니라 가지고 있는 창을 무엇이 차지할지에 대한
**정책**이라고 논문은 주장합니다.

가져갈 통찰은 이것이 이미 문헌을 가진 시스템 문제라는 점입니다. paging, eviction,
tiering, interrupt는 오래전에 풀린 문제이고, 창을 물리 memory로 다루면 그 어휘가
통째로 딸려 옵니다.

## 한계

논문에 한계 절이 없으므로, 아래는 지면에서 읽은 것이 아니라 설계에서 읽어 낸
것입니다.

- **정책이 prompt에 삽니다.** memory 계층과 그 규칙이 system instructions에
  기술되고 모델의 판단으로 실행됩니다. 강제하는 것이 없으므로 instruction
  following의 모든 신뢰성 문제를 물려받고, 런타임 오류가 processor에게 돌아간다는
  논문 자신의 언급이 모델이 얼마나 자주 틀리는지의 표시입니다.
- **eviction이 손실을 내고 그것이 누적됩니다.** 재귀적 요약은 요약의 요약입니다.
  flush마다 다시 압축되므로, 어떤 반영도 보존하지 않은 이른 세부는 raw 메시지가
  기술적으로 recall storage에 남아 있더라도 주기마다 닳아 갑니다.
- **자기 주도 memory는 자기가 낸 손실을 뜻합니다.** 압박 경고가 왔을 때 모델이
  어떤 사실을 저장할 값어치가 있다고 알아보지 못하면, 그것은 창에서 사라지고
  모델이 검색을 돌릴 생각을 해야만 되찾을 수 있습니다.
- **working context가 고정 크기이므로** 오래 갈 층에 단단한 천장이 있고, 넘침이
  모델이 처리해야 할 오류로 드러납니다.
- **믿을 만한 function calling에 의존하며**, 이 논문이 쓰일 당시에는 지금보다
  훨씬 불확실했습니다.

논문 자신의 전망은 더 나은 memory tier 기술과 **개선된 control flow 및 memory
관리 정책**에 관한 것이고, 여기의 정책이 첫 시도라는 공정한 인정입니다.

## 실무에서 의미하는 것

1. **이것을 retrieval과 가르는 질문: 지식이 실행 바깥에 있는가, 실행이 만들어
   내는가.** 문서, 정책, 제품 데이터의 정적 corpus는 2005.11401의 문제입니다.
   필요할 때 가져오고, 인용하고, 끝이고, 결정하는 것은 당신의 코드입니다.
   사용자가 세 세션 전에 한 말, 무엇이 결정됐는지, 무엇을 이미 시도했는지 —
   그것은 실행이 만들어 내고, 쌓이고, 고정된 index에 대한 유사도 검색으로는
   관리되지 않습니다. 거기서 어려운 부분은 찾기가 아니라 **무엇을 남길지
   정하기**입니다.

2. **context를 의도적으로 층으로 나누세요. 층마다 값이 다릅니다.** 창 안에
   그대로, digest로 압축, 또는 아예 바깥에 두고 포인터만. 오래 도는 agent
   context의 대부분은 세 번째 층에 속하는데 사고로 첫 번째 층에 들어앉고,
   그것이 기본 실패이며 매 턴마다 돈이 나갑니다.

3. **나이가 아니라 값어치 순으로 자르세요.** FIFO 설계가 부르는데 스스로는 하지
   않는 교정입니다. 오래된 스무 턴을 대체한 digest는 구조상 창에서 가장 오래된
   비앵커 항목이므로, 가장 오래된 것부터 버리는 정책은 정확히 당신이 압축해 둔
   것을 버리고 그 뒤에 온 잡담을 남깁니다. 항목마다 층을 주고 raw 턴을 압축된
   것보다 먼저 희생하세요.

4. **절대 밀려나면 안 되는 것이 있습니다.** system prompt, task, 그리고 agent가
   지켜야 하는 제약은 앵커입니다. 나이만으로 다듬는 예산기는 결국 그 일을
   정의하는 지시를 버리고, 증상은 agent가 이유 없이 나빠지는 것으로 보입니다.

5. **memory pressure 경고를 구현 세부가 아니라 설계 패턴으로 다루세요.**
   조용히 잘라 내는 대신 eviction *전에* 상태를 저장할 기회를 모델에게 주는 것이,
   우아한 성능 저하와 데이터 손실의 차이입니다. 일반형은 이것입니다. 하네스가
   context를 파괴하려 할 때는 먼저 모델에게 알리세요.

6. **compaction은 실제로 자리를 아껴야 하고, 그러지 못할 수 있습니다.** 거의 모든
   문장이 식별자를 지고 있는 이력에서 문장을 통째로 남기는 추출 요약은 대체하려던
   것보다 길어질 수 있습니다. digest에 상한을 걸고, 대체 대상과 비교하고, 이기지
   못하면 돌리지 마세요. 아무것도 아끼지 못하는 compaction은 순손실입니다.

7. **포인터는 따라갈 수 있을 때만 층입니다.** 세 번째 층은 포인터가 노트 이름을
   대고, 크기를 말해서 여는 것이 token 값어치를 하는지 모델이 판단할 수 있게
   하고, 그것을 여는 tool과 함께 올 때 작동합니다. 해결할 방법이 없는 참조는
   층의 옷을 입은 막다른 길입니다.

8. **다듬기가 메시지 모양을 깨고, 그 깨짐이 무관해 보이는 버그로 나타납니다.**
   사용자 턴 둘 사이의 assistant 턴을 버리면 사용자 메시지가 연달아 놓이고, 첫
   사용자 턴을 버리면 목록이 assistant 메시지로 시작할 수 있습니다. API가 항의한
   뒤 재시도에서가 아니라 다듬는 자리에서 정규화하세요. 더 기묘한 실패도 있습니다.
   나이만으로 다듬은 이력은 결정이 이미 단언되어 있고 assistant가 이미 동의한
   채로 중간부터 열리는데, 이는 거짓 전제를 받아들이게 하려고 심어 둔 대화와
   똑같은 모양이고 모델이 그런 context를 아예 거절할 수 있습니다. digest가 이것도
   부수적으로 고칩니다. 조용한 공백을 남기는 대신 자기가 무엇을 대신하는지
   선언하기 때문입니다.

채인 같은 고정 크기 working context입니다.

## lab과의 연결

`papers.yaml`은 이것을
`labs/track-2-tools-context/11-context-memory`에 연결하며, 그 lab이 OS 비유를
걷어내고 정책 질문을 날카롭게 만든 실무자판입니다.

**lab의 세 층이 이 논문의 계층을 결정으로 바꿔 말한 것입니다.** 무엇이 창 안에
그대로 있어야 하고, 무엇이 digest로 압축될 수 있고, 무엇이 파일에 있고 창에는
포인터만 두어야 하는가. 논문이 메커니즘을 기술하는 곳에서 lab은 당신의 내용물을
분류하라고 요구하고, 그것이 옮겨지는 부분입니다.

**`budget_messages`가 논문이 모델 판단에 맡긴 eviction 정책을 공급합니다.**
앵커는 절대 버리지 않고, 나머지는 층 단위로 층 안에서 오래된 것부터 버려서 raw
턴이 digest보다 먼저 희생됩니다. 그 순서가 3번이고, 순수 FIFO에 대한 교정입니다.
lab은 그 장치까지 지킵니다. 남은 비앵커 메시지를 버릴 수 있는 마지막 pass를 두어,
층 이름의 오타가 무언가를 창에 영원히 고정하지 못하게 합니다.

**`compact`가 재귀적 요약에 필요한 검사를 더합니다.** digest에 상한을 걸고,
대체 대상보다 작아지지 않으면 compaction을 거절하고, raw 이력이 이미 들어가면
아예 건너뜁니다. 논문은 임계를 넘으면 무조건 flush하고, lab은 그 flush가 값을
하는지 묻습니다.

**`Scratchpad`와 `scratchpad_index`가 archival storage를 구체화한 것이고**,
포인터가 노트와 크기와 그것을 여는 tool을 대야 한다는 lab의 요구가 7번이
요구하는 바입니다. `READ_NOTE_TOOL`, `run_read_note`와 짝지으면, 그것이 전용
런타임이 아니라 평범한 tool 호출로 지은 이 논문의 자기 주도 retrieval입니다.

lab에는 있고 논문에는 없는 것이 둘. `to_api_messages`가 예산 배정이 깨뜨린
메시지 모양을 정규화하고, 그것이 8번입니다. 그리고 측정에 관한 lab의 마지막
경고. 빈 답은 나쁜 답이 아니고, 거절이나 `max_tokens`로 끝난 실행은 창에 무엇이
있었는지와 무관하므로, context 전략이 실패했다고 결론짓기 전에 `stop_reason`을
읽으세요. 예산을 조정하는 것과 전혀 엉뚱한 것을 조정하는 것의 차이입니다.
